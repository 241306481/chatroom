开始使用

  • 第一个注册的账号会自动成为超级管理员。注册后请尽快在个人资料和安全设置中检查昵称、头像与密码。
  • 站内内容按“域”组织，每个域下有多个讨论区。进入域后可以查看讨论、域文件和成员。
  • 顶栏提供讨论入口、消息搜索、私信、通知和主题切换；窄屏下导航区域可以横向滚动。
  • 个人主页可以修改资料、查看关注关系，并在“安全设置”中调整私信接收范围。

讨论与私信

讨论区

  • 消息支持 Markdown、LaTeX、图片和附件。输入 @昵称 可以提及成员，点击消息上的操作可以回复、回应或查看源码。
  • 置顶、撤回和删除是否可用取决于你的系统权限与域内权限；撤回不会在广播中泄露原文。
  • 讨论管理员可以批量置顶、修改标题或删除讨论，详见批量操作。

私信

  • 在“私信”页点击“新增会话”搜索用户，或从用户主页发起会话；未读数量会显示在会话列表和顶栏。
  • 私信接收范围可在“安全设置”中设为所有人、互相关注、关注我的人或仅管理员。
  • 私信支持 Markdown、图片和附件，也支持未读统计和单侧删除；删除自己这边的会话不会删除对方的消息。

文件与附件

  • “我的文件”属于个人空间，可上传、下载、复制链接、重命名和置顶。文件默认隐藏，设为公开后其他用户可通过链接访问。
  • 域文件属于整个域，上传、下载和删除由域内文件权限控制，可查看的文件取决于你的角色。
  • 编辑器上传的图片会插入为 ![名称](地址)；附件也可以这样展开，或用 @ 引用为紧凑卡片。
  • 浏览器支持时 PDF 会直接内嵌预览；不支持时会显示“打开”入口。单个上传大小上限由管理员配置。
  • 文件页支持批量下载为 ZIP、批量删除和批量修改可见性，详见批量操作。

搜索

消息搜索只返回你有权访问的域和讨论。可以按域、讨论和用户筛选，也支持高级语法：

  • from:昵称或UID：按发送者过滤。
  • in:讨论ID：只在指定讨论内搜索。
  • domain:域名：只在指定域内搜索。
  • before:YYYY-MM-DD、after:YYYY-MM-DD：按日期过滤。
  • "精确短语"：引号内按字面量搜索，不解析高级语法。
  • 多个条件用空格分隔，表示同时满足，例如 from:2 in:general after:2026-01-01。

编辑器

Markdown 与 LaTeX

输入区支持 Markdown、LaTeX 公式、代码高亮、表格、引用、任务列表等。

  • 粗体：**文字**，可用 Ctrl+B
  • 斜体：*文字*，可用 Ctrl+I
  • 下划线：<u>文字</u>，可用 Ctrl+U
  • 代码块：连续三个反引号或直接用按钮包裹，Ctrl+Enter 可发送消息
  • 公式：行内 $...$，独立块 $$...$$

上传与粘贴

工具栏里的图片按钮和附件按钮都可以上传文件。在讨论中会保存为讨论附件，在私信中会保存为当前会话附件。

截图后可以直接在输入框按 Ctrl+V 粘贴图片，编辑器会自动上传并插入 Markdown 链接，无需先保存成文件。上传失败时会提示权限、大小或网络错误。

图片会被插入为 ![名称](地址)。附件以后可用 ![名称](地址) 展开查看，或用 @ 引用为一个紧凑卡片。

快捷键

  • Ctrl+B / Ctrl+I / Ctrl+U：粗体、斜体、下划线。
  • Ctrl+Enter：发送消息。
  • 表格、链接、代码块和公式可通过工具栏插入。

批量操作

文件页、讨论管理页和管理后台支持先勾选项目，再使用工具栏统一处理。表头复选框可全选当前列表。

  • 文件：批量置顶、取消置顶、修改可见性、重命名、下载 ZIP、删除。重命名支持查找替换、统一前缀、统一后缀；下载单次最多 200 个文件、总计 100 MB。
  • 讨论：批量置顶、取消置顶、修改标题、删除；讨论 ID 不会改变，general 不可删除。
  • 讨论消息：点击“选择”后勾选消息，可批量置顶或删除，单次最多 100 条。
  • 管理后台：批量封禁/解封用户，批量通过或拒绝加入申请。

批量操作会先检查所有选中项目；只要有一项无效或无权操作，整批都不会执行。

权限与管理

  • 系统权限控制全局能力，域内权限控制单个域中的操作。部分敏感操作要求同时满足系统权限和域内权限。
  • 系统管理面板可管理用户、系统角色、系统权限、加入申请、IP 封禁、限流和用户最近 IP。
  • 域管理面板可管理域设置、成员、角色、讨论和域文件。只有具备相应管理权限的入口才会显示。
  • 管理员还可以配置站点名称、注册开关、上传大小和站点公告等系统设置。
  • 被封禁的用户无法登录或继续操作；IP 封禁和限流用于处理滥用行为，启用反向代理时应正确配置 TRUST_PROXY。
